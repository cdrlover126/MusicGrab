﻿# 乐取 MusicGrab v1.8.0 发布说明

发布日期：2026-10-28
平台：Windows x64（Windows 10 / 11）

## 1. 本版要点

**围绕「输出质量」「导入方式」和「失败处理」重做了一轮体验：**

| 能力 | 说明 |
|---|---|
| 格式体系 | MP3 / M4A / Opus / FLAC / WAV / **BEST（源格式不转码）** |
| 音质体系 | **V0（LAME 最佳 VBR）**、320 / 256 / 192 / 128 / 96 kbps CBR、自定义 32–320 |
| 不转码 | BEST 直接复制源音轨，零损失、速度最快；按源编码自动选择容器 |
| 封面嵌入 | 抖音 / 快手 / 酷狗 / yt-dlp 站点自动抓封面写入音频；本地视频抽帧作封面 |
| 拖放导入 | 视频文件、整个文件夹、浏览器标签页/选中链接可直接拖进窗口；文件夹递归扫描、自动去重 |
| 转换报告 | 默认覆盖同名 `转换报告.csv`，输出目录只留一份；可切换为每次新建或完全不生成 |
| 任务重试 | 「任务结果」表格逐条展示，右键**单条重试**，顶部**一键重试全部失败项**，编号保持不变 |

## 2. 完整变更

### 新增

- **任务结果「音质」列**：转换成功后用 mutagen 直接探测输出文件的真实音质参数
  - 码率（kbps）· 采样率（kHz）· 声道数（单声道/立体声/N 声道）
  - 无损格式（FLAC / WAV / BEST 复制音轨）额外显示位深（如 `16 bit`）
  - 同一列同步写入 `转换报告.csv`（旧 reports 无此列，新批次即有）
  - 下载阶段本身已是"最高质量优先"：快手按码率从高到低排序候选地址，通用引擎取 yt-dlp 的 bestaudio

- **双形态分发**：同一个构建脚本产出两种包
  - **单文件版** `MusicGrab-v1.8.0-win-x64.zip`：`MusicGrab.exe` 单个文件，双击即用（实测启动约 1.96 秒，每次启动要把 100 MB 解压到 `%TEMP%`）
  - **目录版** `MusicGrab-v1.8.0-win-x64-folder.zip`：`MusicGrab\` 文件夹，**实测启动约 0.48 秒（快 4 倍）**，没有 `%TEMP%` 临时解压目录（顺带根治了 CA 证书包临时目录被清理、退出时"清理临时目录失败"两个问题）
  - 目录版里组件可放在 exe 旁边的 `MusicGrab_components\`，整个文件夹拷到 U 盘即可继续用
- **程序自身的版本更新**（GUI「输出设置 → 程序版本」）
  - **默认零托管**：不联网、不依赖任何服务器，只显示当前版本并给出升级指引
  - 可选：配置版本清单地址后自动比对版本号，发现新版本可一键下载
  - 下载官方发布包并**校验 SHA256**（不符即删除并报错），解压到程序目录旁的 `MusicGrab-1.8.1\`
  - 弹窗指引用户手动覆盖正在运行的程序（运行中的 exe 无法安全重写自己）
  - 清单地址支持 HTTP(S) 与**本地文件路径**（内网共享目录 / U 盘，完全离线可用）
- **`packaging/make_manifest.py`**：生成版本清单 `dist/release/latest.json`
- **BEST（源格式不转码）**：`-f best` / GUI「输出格式 → BEST」
  - 先探测源音频编码，再决定输出扩展名（mp3→`.mp3`、aac→`.m4a`、opus→`.opus`、vorbis→`.ogg`、flac→`.flac`、pcm→`.wav`）
  - 未知编码沿用源文件扩展名，无扩展名时用 `.mka`（Matroska 音频几乎兼容所有编码）
  - 复制音轨时不再强制采样率 / 声道，避免 ffmpeg 被迫重编码
- **V0 可变码率**：MP3 使用 LAME `-q:a 0`；其他有损格式回落到 320k
- **96 kbps CBR 预设**，固定码率预设置补全为 96 / 128 / 192 / 256 / 320
- **封面嵌入**（`converter.convert_to_audio(..., cover=...)`）
  - 抖音：`video.cover` / `origin_cover` / `dynamic_cover`
  - 快手：`coverUrl` / `poster` / `coverUrls` / `webpCoverUrls` / `thumbnailUrl`
  - 酷狗：`album_spic` / `imgurl` / `album_img` 等
  - yt-dlp 站点：`thumbnail` / `thumbnails`
  - 本地视频：ffmpeg 抽第 1 秒的一帧
  - WAV / Opus 容器不支持封面，自动跳过；封面下载失败不阻断转码
- **拖放导入**
  - 把视频 / 音频文件、整个文件夹拖进窗口，自动追加到输入框
  - 文件夹递归扫描，过滤受支持的音视频；单次最多 2000 个，跳过隐藏目录 / 回收站 / `__MACOSX` / `node_modules`
  - 新增「添加文件夹…」按钮；所有导入按 URL / 绝对路径自动去重
  - **浏览器标签页 / 链接拖放暂时关闭**：各浏览器给出的 MIME 数据差异太大、实际体验不稳定，先只保留文件与文件夹拖放；网址复制后粘贴效果一样。恢复只需把 `dragdrop.ALLOW_LINK_DROP` 改成 `True`
- **转换报告保存方式**（GUI「输出设置 → 转换报告」，CLI `--report`）
  - `overwrite`（默认）：固定写 `转换报告.csv`，每次覆盖，输出目录最多留一份，并清理历史遗留的时间戳报告
  - `history`：每次新建 `转换报告_YYYYMMDD_HHMMSS.csv`，保留全部历史
  - `none`：不生成报告
- **任务结果面板**：序号 / 状态 / 标题 / 歌手 / 时长 / 大小 / 输出文件
  - 右键：打开文件、打开所在文件夹、复制来源地址、重试此任务
  - 顶部：重试全部失败项、打开输出目录
  - 重试沿用原任务的序号（如第 7 条重试后仍输出 `007_xxx`），不会重新编号
- `BatchProcessor.run(lines, indices=[...])`：支持指定任务编号，供重试复用
- 新增单元测试：V0 / BEST 扩展名映射 / 码率规则 / 封面嵌入 / 任务编号 / 路径去重 / 文件夹递归扫描 / 拖放格式解析 / 报告保存方式

### 变更

- 版本号 1.7.0 → **1.8.0**
- 输出格式精简为 6 种：**移除 AAC（ADTS 裸流）、OGG Vorbis、WMA**
  - 旧参数 `-f aac` / `-f ogg` / `-f wma` 不再接受；请改用 `m4a` / `opus` / `mp3`
- GUI「音质」下拉框重排：V0 置顶并标注「推荐」，默认仍为 320
- GUI 增加格式/音质说明文字：无损与 BEST 会自动禁用或忽略码率设置
- CLI `-q` / `-f` 帮助文本同步更新
- 转换日志与 CSV 报告记录可读音质描述（如 `V0 最佳 VBR（推荐）`）

### 修复

- **B站链接无法处理**（报 `The extracted extension ('html') is unusual and will be skipped for safety reasons. `）：浏览器从收藏/分享复制出的链接常带 `/zh-Hans/` 语言前缀、`trackid` 等跟踪参数、`m.bilibili.com` 移动端域名，甚至 `b23.tv` 短链——这些形态 yt-dlp 的 BiliBili 提取器都认不出，掉进 generic 万能提取器后把网页 HTML 本身当成一个"格式"。现在批量处理前会把 B站链接**归一化**为规范形式（去语言前缀、去跟踪参数、归一移动端域名、解析 b23.tv 短链），再交给 yt-dlp。
- **组件目录支持便携模式**（面向单文件分发场景）
  - 组件（外置 yt-dlp / ffmpeg）优先放在 **exe 同目录的 `MusicGrab_components\`**：exe 拷到别的机器、U 盘，和组件一起带走即可，不会重新下载
  - exe 所在目录不可写（如 `Program Files`）时自动退回机器级目录 `%LOCALAPPDATA%\MusicGrab\`
  - 两个目录都存在时便携目录优先；同一台机器上的多个 exe 副本仍可共用机器级目录里的组件
  - import finder 改为同时搜索多个根目录
- **组件版本状态自描述**：版本号跟着组件本身走（yt-dlp 包内 `version.py`、ffmpeg 目录内 `version.txt`），
  `state.json` 降级为只存偏好（「忽略此版本」、启动检查开关）。清理工具删掉状态文件、或 exe 换了机器，
  都不会再出现「明明升级过了又提示有更新」
- **「恢复内置组件」入口**：GUI「输出设置 → 组件更新 → 恢复内置组件」可删除外置副本、回到打包内置的版本
- **每次启动都提示「组件有更新」，明明已经升级过了**（用户实测反馈）
  - 根因：ffmpeg 组件升级时**只把二进制**装进覆盖层，并不替换 `imageio-ffmpeg` 这个包，
    于是「当前版本」永远停在打包时内置的旧值（0.6.0），拿它和 PyPI 最新版（0.7.0）比，
    每次启动都判定为「有更新」
  - 现改为：覆盖层里有外置 ffmpeg 时，以**升级时记录在 `state.json` 里的版本**为准；
    没有记录时才退回打包内置的包版本。yt-dlp 侧也补上了同样的兜底
    （覆盖层版本文件缺失时用记录值，再用打包内置值）
  - 组件已是最新时，自动清理无意义的「忽略此版本」记录（网络异常时保留）
- **拖放被界面控件截胡**（用户实测反馈）
  - 根因：Qt 的 `findDnDTarget()` 会把拖放交给「从光标处向上第一个 `acceptDrops` 的控件」，而 `QLineEdit` / `QPlainTextEdit` / `QTextEdit` **默认 `acceptDrops=True`**——日志框（只读）、输出目录等输入框会把拖放吃掉，主窗口收不到，表现为「拖进程序没反应」。现关掉除输入框外所有子控件的拖放接收，由主窗口统一接管
  - 拖放数据解析同时兼容 `text/uri-list`、`text/uri-list;charset=utf-8`、`text/x-moz-url`（Firefox）与纯文本网址
- **组件更新检查报「Could not find a suitable TLS CA certificate bundle」**（用户实测反馈）
  - 根因：打包版把 CA 证书包解压在 `%TEMP%\_MEIxxxxxx` 里，该临时目录被「清理临时文件」工具删除后，所有 HTTPS 请求都会失败
  - 现启动时把证书包复制一份到覆盖层目录（`%LOCALAPPDATA%\MusicGrab\cacert.pem`），请求时 certifi 路径失效就自动改用这份副本；解析、下载、组件自检三条链路都走同一套兜底
- **转换报告越用越多**：原先每次批量都新建 `转换报告_时间戳.csv`，输出目录很快堆满文件。现默认覆盖同名 `转换报告.csv` 并清理历史遗留报告，可切换为「每次新建」或「不生成」
- **`--skip-existing` 从未生效**：原实现先调用 `_unique_path()` 生成"保证不存在"的路径，
  再判断 `path.exists()`，结果永远为假。现改为用稳定的 `_base_path()` 判断同名文件，
  存在才跳过；实际写入仍走去重编号。
- 日期型版本/码率参数混用导致的边界问题（`v0` 不再被当成非法整数）
- 重试任务的日志编号：`[7/2]` 修正为 `[1/2]`（文件名仍保留原序号 `007_`）
- 进度条在失败/跳过时不再停滞（按完成条数推进）

## 3. 兼容性提示

- 配置文件与覆盖层（`%LOCALAPPDATA%\MusicGrab\`）保持兼容，可直接覆盖升级
- 旧版输出格式 `aac` / `ogg` / `wma` 已移除；批量脚本如使用请替换：
  - `aac` → `m4a`
  - `ogg` → `opus`（或 `m4a`）
  - `wma` → `mp3`
- `best` 的输出扩展名由源音频决定，脚本中不要写死 `.mp3`

## 4. 运行环境

- 操作系统：Windows 10 (1809+) / Windows 11，x64
- 免安装、免 Python 环境；单文件版双击运行，目录版解压后运行 `MusicGrab\MusicGrab.exe`
- 首次使用境外平台需在「输出设置 → 代理」填入本地代理地址（如 `http://127.0.0.1:7890`）
- 首次运行联网以检测代理可达性；本地视频转码可完全离线
- 组件自检需要访问 PyPI；不通时程序照常工作（只是不提示更新）
- 程序自身的版本检查需要能访问版本清单地址；未配置时该功能不启用

## 7. 已知限制

- 平台付费/VIP 内容需登录，本程序不提供绕过
- 抖音风控为平台策略，偶发失败内置 3 次重试
- 内置 FFmpeg 缺少 `mpegps` 解复用器，**不支持 VOB 容器**
- WebM 仅支持 Vorbis/Opus 音频轨
- YouTube 部分视频需 PO Token，由 yt-dlp 侧限制
- 封面嵌入不支持 WAV / Opus（容器无标准封面位置）
- BEST 模式不改变源编码；若源为低码率音轨，输出仍是低码率
- yt-dlp 升级需**重启程序**后生效（当前会话已加载的模块无法热替换）
- 组件自检只覆盖 yt-dlp 与 ffmpeg，**不检查应用自身版本**
- MSIX 打包与签名需 Windows SDK，当前发布形式为 exe
